SECTION 1

General

1-1.PURPOSE. This manual describes conn and its operation.

1-2.SCOPE. The station serves one operator directing many hands on one machine. It shows the processes running in each project, what each is doing, and which one is waiting for the operator, and it puts the operator in front of any of them. It does not edit files, run builds, or hold conversations. The hands do.

1-3.DEFINITIONS. Terms used in this manual.

OperatorThe person using conn.
HandA process conn watches: a shell, an AI, or a command a shell is running. Also called a station hand.
AIAn artificial intelligence: an assistant running in a terminal, such as Claude Code, that works a place and can stop to wait for the operator.
PlaceThe project directory a hand runs in: a git repository, or a folder that holds several repositories.
StandingThe state conn reports for a hand: WORKING, ACTIVE, IDLE, or WAITING.
WaitingThe standing of an AI that has stopped and needs an answer from the operator, such as a permission or a question.
ContactA conversation with an AI, from raising it to ending it. Its record is the transcript.
ConsoleThe page conn comes up on. It reads out the machine and gives a verdict.
RailThe left pane of the window, forty-four columns wide. The watch and the other views are shown there.
WatchThe list of hands, grouped by place, in the order they started.
SlotThe right pane of the window. It shows one hand.
LookA page on one row of the watch, shown in the slot.
ListEvery project under the roots, running or not, shown on the rail.
PickerThe conversations suspended at a place, shown on the rail.
BarThe status line at the bottom of the window. It shows the state of the keys on the left and one lamp per hand on the right.

1-4.INDICATIONS. The station indicates two things: what each hand is doing, and which hand is waiting. The watch and the lamps on the bar show the first. The word WAITING on the watch, blinking, and a lamp on the bar in the same color show the second; tab goes to it (4-3).

1-5.COMMANDS. The command alone brings up the console and continues to the watch. Other commands are given by name after it. --light and --dark set the ground, ahead of a command if one is given.

SYNOPSIS

COMMANDDOES
connBrings up the console, then the watch.
conn downTakes the server down with everything in it, and reports what went.
conn theme claudeWrites conn's theme for Claude Code.
conn theme vimWrites conn's colorscheme for nvim.
conn --lightSets the ground light.
conn --darkSets the ground dark.
conn --helpPrints this table.
conn --versionPrints the build.

SECTION 2

The Station

2-1.ARRANGEMENT. The station is one window of a tmux server that conn holds. The rail is on the left and the slot on the right. The bar runs under both. Figure 2-1 shows the arrangement.

┌──────────────────────────────┬─────────────────────────────┐
│ RAIL                         │ SLOT                        │
│                              │                             │
│ KIND   COMMAND    AGE STATUS │ The hand reached from the   │
│                              │ rail: a shell, an AI, a run │
│ w0zro/conn                   │ or the look. The keys are   │
│ SHELL  zsh        2H    IDLE │ here while a hand is.       │
│ ▸ AI   claude     1H WAITING │                             │
│                              │                             │
├──────────────────────────────┴─────────────────────────────┤
│ BAR  PREFIX                                    ● ● ● ●   │
└────────────────────────────────────────────────────────────┘

FIGURE 2-1. STATION ARRANGEMENT

2-2.THE SERVER. conn holds a tmux server of its own. Its socket is under ~/.local/state/conn, or where CONN_SOCKET says. The first conn brings the server up and puts the terminal on it. A later conn attaches to what is there. Everything in the server stays until the server is taken down (5-2). A hand that leaves the slot goes to a window of its own, out of sight, and keeps running.

2-3.COMING UP. To bring up the station:

1.Type conn.
2.The console comes up. It reads out the machine, runs the start-up checks, and gives its verdict: ALL SYSTEMS NOMINAL, or the count of systems that are not.
3.Press any key. The watch comes up on the rail and the slot opens beside it.

2-4.THE CONSOLE. c on the watch brings the console back over the whole window. Any key returns to the watch.

2-5.THE PREFIX. Chords are given under ctrl-space. CONN_PREFIX names another prefix, in the spelling tmux uses. While a chord is open, PREFIX is lit on the bar. No other tmux key is bound.

CHORDDOES
ctrl-space -Puts the keys on the rail, from anywhere in the server.
ctrl-space pOpens the list, from anywhere in the server (3-7).
ctrl-space tabGoes to the AI that has waited longest (4-3).
ctrl-space ctrl-spaceGoes to the hand that was last in the slot (4-4).
ctrl-space qDetaches (2-6).

2-6.STANDING DOWN. q on the rail detaches the terminal from the server. ctrl-space q does the same from anywhere in it. The server and every hand in it keep running, and the next conn attaches to them. Ending the server is procedure 5-2.

2-7.WITHOUT TMUX. Without tmux on the path, conn shows the console and the watch and reaches nothing. On macOS the watch needs lsof, which is how it reads where a process is working.

2-8.THE GROUND. The server comes up on a dark or a light ground. The first time it rises it asks the terminal for its background and keeps the answer for the life of the server. conn --light and conn --dark set the ground instead, for a server coming up or one already up. Every pane takes the new ground.

2-9.THEMES. A program that draws its own colors takes none of the server's. conn theme claude writes a theme for Claude Code and offers to select it. conn theme vim writes a colorscheme for nvim, taken with colorscheme conn. Each is drawn on the ground the server is on.

2-10.ENVIRONMENT. The station reads three variables.

VARIABLESAYS
CONN_ROOTSWhere the list looks for projects, as a path list. ~/projects when unset.
CONN_SOCKETWhere the server's socket is.
CONN_PREFIXThe prefix for chords, in the spelling tmux uses. C-Space when unset.

SECTION 3

Watch Procedures

3-1.THE WATCH. The watch lists the hands by place. A place is titled by its path below the root; a place outside every root is written from ~. Under a place the hands are shown as a tree: a shell, and what it runs indented under it. Each row shows the kind, the command, the age, and the standing. On the console, which is wider, the terminal is shown too. A row keeps its position for as long as its hand lives, oldest first, and a new row goes on the end. With nothing running the watch says NOTHING ON WATCH.

3-2.STANDINGS. The last column of a row is its standing.

STANDINGMEANS
WORKINGDid something between one reading and the next. An AI is WORKING when it is mid-turn, or when a command is running under it.
ACTIVEAlive and doing nothing.
IDLEA shell at its prompt, or an AI whose turn is over. Nothing is pending.
WAITINGAn AI stopped on something it needs from the operator. The word blinks.
STOPPEDSuspended. Shown as a chip.
ENDEDFinished and not yet collected. Shown as a chip.

3-3.WHO IS WAITING. Only an AI that says its own standing is ever WAITING. Claude Code says it, and says when its standing changed. An AI conn cannot ask reads as WORKING or ACTIVE from the processor time it spends. conn does not guess.

3-4.KEYS ON THE WATCH. The cursor is on one row. It follows its hand from one reading to the next.

KEYDOES
j, kMove the cursor. The arrows do the same.
enterPuts the hand under the cursor in the slot, with the keys in it.
tabGoes to the AI that has waited longest (4-3).
sOpens a shell at the place under the cursor.
aRaises an AI at the place under the cursor (4-2).
alt-aOpens the picker over the conversations suspended at the place (4-5).
iOpens the look on the row under the cursor. Pressed again, closes it (3-6).
xAsks to end the hand under the cursor (4-6).
pOpens the list (3-7).
cBrings the console back over the window (2-4).
qDetaches (2-6).

3-5.HELD AND REPORTED. A row conn holds a pane for is in the ink, and enter reaches it. A row conn can only report, a terminal it did not open, is dimmed. The cursor goes to it and nothing else does. The row in the slot carries its kind in orange. Outside the server every row is reported.

3-6.THE LOOK. The look is a page on one row, shown in the slot. It says what the row has no room for: the whole command, the directory, the time up and the processor time spent, what runs it and what it runs; of an AI, the conversation it is carrying and what it is stopped on; of the place, what git says of it. To read a row:

1.Put the cursor on the row.
2.Press i. The look opens in the slot. The keys stay on the rail.
3.j and k move the look with the cursor. tab carries it to the AI that is waiting.
4.Press i again. The look closes. Where the row is one conn holds, its hand takes the slot.

NOTE

conn look 1234, from a shell in the server, pins the look to one process instead of the cursor.

3-7.THE LIST. The list is every project under the roots, whether anything is running in it or not. A folder that holds several repositories is a row with them under it. To open a hand at a project:

1.Press p on the watch, alt-p from any view, or ctrl-space p from anywhere in the server.
2.Type to narrow the rows. backspace and ctrl-u edit the line. The arrows, or ctrl-p and ctrl-n, move the cursor.
3.Press enter. A shell opens at the project and the watch returns with it in the slot. ctrl-a raises an AI there instead (4-2). alt-a opens the picker (4-5).
4.esc returns to the watch with nothing opened.

3-8.THE BAR. The bar is dark at rest. The left half lights for a state of the keys. The right half is one lamp per row of the watch, in the order of the watch.

INDICATIONMEANS
PREFIXA chord is open. The next key is one of 2-5.
COPYThe pane with the keys is in copy mode.
CONFIRMA kill is armed. The question stands beside it (4-6).
Lamp, grayThe row is WORKING.
Lamp, faintThe row is ACTIVE or IDLE.
Lamp, blinkingThe row is WAITING, in the color the word is.

SECTION 4

Contact Procedures

4-1.CONTACT. A contact is a conversation with an AI, from raising it to ending it, and its record is the transcript the AI writes. conn raises Claude Code, and the procedures of this section are written for it. Another AI on the watch is a hand like any other: it is reached, put in the slot, and ended the same way. conn cannot ask it its standing, so it is never WAITING.

4-2.RAISING AN AI. To start an AI at a place:

1.On the watch, put the cursor on any row of the place. Or open the list (3-7) and put the cursor on the project.
2.Press a. On the list, press ctrl-a.
3.A shell opens at the place running claude, takes the slot, and has the keys. Its row is on the watch under the place, kind AI.
4.conn tells the AI where it is: that it runs in a pane of the station, and how to start anything long-lived in a window of its own, so the watch shows it and the operator can reach it.

NOTE

What conn tells the AI travels with conn. Nothing is written into the settings of the AI.

4-3.ANSWERING AN AI. When an AI stops on something it needs from the operator, its row reads WAITING, blinking, and its lamp on the bar blinks with it. To answer it:

1.Press tab on the watch, or ctrl-space tab from anywhere in the server.
2.The cursor goes to the AI that has waited longest. Its pane takes the slot and the keys land in it.
3.Answer it.
4.Press tab again for the next, longest first, and round again from the end.

4-4.WORKING TWO HANDS. ctrl-space ctrl-space goes to the hand that was last in the slot, and pressed again comes back. It is the key for a shell and the AI being asked about it, or a build and the file it fails on. A vacant slot and the look are not remembered. alt-o does the same from the rail.

4-5.RE-ESTABLISHING CONTACT. A conversation does not end with the AI. Its record is enough to pick it back up. To continue one:

1.On the watch, put the cursor on any row of the place. Or open the list and put the cursor on the project.
2.Press alt-a. The picker lists the conversations suspended at the place, newest first, each by its branch, the last thing it was asked, and its age. Type to narrow the rows.
3.Press enter. A shell opens running claude --resume on that conversation and takes the slot.
4.esc returns to the watch with nothing continued.

NOTE

A conversation a live AI is carrying is not listed. The picker checks the process table rather than the record alone.

4-6.ENDING AN AI. To end an AI:

1.Put the cursor on its row and press x.
2.CONFIRM lights on the bar, with the question beside it: END CLAUDE 1234 · X CONFIRMS · ANY OTHER KEY CANCELS.
3.Press x, y, or enter. The AI is asked to end. The shell it ran in is left at its prompt. Any other key cancels.
4.The watch reads again after a beat, and the row goes when the AI has.

NOTE

An AI ended this way keeps its record. Procedure 4-5 continues it.

SECTION 5

Emergency Procedures

5-1.A HAND THAT WILL NOT END. x asks a hand to end with the signal a well-behaved command answers by saving and shutting down. A bare shell ignores that signal and is killed outright instead; there is nothing in it to save. A hand that ignores the request stays on the watch. Reach it with enter and end it from inside.

5-2.TAKING THE STATION DOWN. To end the server and everything in it:

CAUTION

conn down ends every hand in the server: every shell, every AI, and every run, in the slot or out of sight in a window of its own. Work that is not saved is lost. A conversation can be re-established afterward (4-5). A run cannot.

1.From a terminal outside conn, or from a shell in it, type conn down.
2.conn reports a line for each window it ended and one for the server.

5-3.THE SLOT EMPTIES. When the hand in the slot ends, the slot takes the next hand conn holds, from the cursor down and round again from the top. With none to take, it shows VACANT. Any key in it puts the keys on the rail.

5-4.THE KEYS ARE ELSEWHERE. From any pane of the server, ctrl-space - puts the keys on the rail. From the rail, enter puts them in the slot.

5-5.THE WATCH CANNOT READ. When the process table cannot be read, the watch shows the reason as a chip in place of its rows and reads again on the next beat. On macOS the usual reason is that lsof gave no answer in time.
