FIGURE 1-1  ·  THE PROCESSES OF ONE MACHINE, UNFILED

1-1. More processes run on a machine than one operator can watch. Each has a terminal of its own. Two have stopped to ask, and nothing says so.

FIGURE 1-2  ·  FILED

1-2. conn files every process under the project it works: a block a project, a row a process, each row marked for what it is. The rows stand by kind, contacts first.

FIGURE 1-3  ·  WHAT EACH PROJECT WANTS

1-3. At the end of a project’s rule is what it wants of the operator: WAITING where a contact has stopped to ask, a fault’s word where something is a fault. A project that wants nothing says nothing.

FIGURE 1-4  ·  THE WORKSPACE

1-4. tab goes to the contact that has waited longest; enter puts its pane in the workspace. The question is answered where it was asked. ctrl-space brings the keys back to the panel.

FIGURE 1-5  ·  DETACHED

1-5. q detaches. The server holds every pane; nothing ends with the operator’s leaving, and the panel is as it was on return.

SECTION 2  ·  INSTALLATION PROCEDURE

2-1. conn is a station for one operator directing many processes on one machine: a panel that lists the processes working each project, and a workspace holding the one the operator is in, on a tmux server conn starts and holds.

$curl -fsSL https://conn.w0zro.com/install.sh | sh
