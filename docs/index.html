CONN

OPERATING MANUAL

A station for one operator directing many processes on one machine.

The station shows the shells, contacts, and commands running in each project, what each is doing, and which one is waiting for the operator. macOS and Linux, on tmux.

SECTION 1

General

1-1. conn is a station for one operator directing many processes on one machine. It runs on tmux, which it starts and holds on a socket of its own. The panel occupies the left of the window, forty-four columns; the workspace is the rest. The panel lists every process working a project, filed by what it needs from the operator. The workspace holds the one process the operator is in.

1-2. A process is anything with a terminal whose working directory is inside a project: a shell, an editor, a build, a dev server. A container compose started for a project, and a Homebrew service a project claims, are processes too. A contact is a process with an agent at the other end, Claude Code, which works on its own and stops to ask. A project is a repository under one of the roots the operator names. The page is what conn knows of the row under the cursor, shown in the workspace while the keys are on the panel.

1-3. This manual says how conn is operated. The reference is the man page: every key, every word the screen shows, every file conn reads and writes. man conn shows it, and ? shows it inside conn, in the workspace.

1-4. The installation procedure on the cover puts the binary in ~/.local/bin and the man page beside it. conn runs on macOS and Linux. It needs tmux on the path, and on macOS lsof, which is how it reads where each process is working. Without tmux, conn shows the console and the panel and can go into nothing.

SECTION 2

First session

2-1. Type conn. The console comes up: the machine, the session, the start-up checks, and the verdict. A check that found something wrong is a fault and blinks; with none, ALL SYSTEMS NOMINAL. Any key continues.

2-2. The first time, conn asks where the work is: a line holding a directory, and under it the directories that answer it. tab fills the line in with the row under the cursor; enter takes it, writes it to ~/.config/conn/config.json as the root, and goes to work. More roots, the theme and the ground are the settings: , opens them in the workspace once conn is at work.

2-3. The panel comes up, a block for each project work is happening in, each at the margin and named by its own directory. At the end of a block’s rule is what that project wants of you: WAITING where a contact has stopped to ask, the fault’s word where something is a fault, DOWN where a declared process is not up. A project that wants nothing says nothing. The rows under it stand by kind — the contacts that can answer you, then the shells you type at, then the work — each marked for what it is and saying what it is doing, and only saying a word at the right where there is one to say: how long a wait has waited, a fault’s word, or the word for what is not running.

   conn ────────────────────────  WAITING
▸  ◆  claude                        9 MIN
   ❯  zsh
 ⣾ ○  go test ./...

   web ─────────────────────────  STOPPED
   ❯  zsh
   ▯  vim                         STOPPED
   ○  node vite                     :5173
   ○  worker                         DOWN

The mark at the head of a row is what the row is: ◆ a contact, ❯ a shell, ▯ an editor, ■ a service, ○ anything else. A contact waiting and a test running at one project; a shell, a stopped editor, a server up and a declared worker down at the other.

2-4. j and k move the cursor. The workspace shows the page for the row: the command in full, where it is working, what it listens on, what runs it and what it runs, and what git says of the project. For a contact the page is a handoff sheet, with the question it stopped on in its own words.

2-5. enter goes in. The row's process fills the workspace and the keys are in it. Work there as in any terminal. ctrl-space brings the keys back to the panel, with the row of the process just left under the cursor, so the next key is about it. This is the one key tmux takes; tmux's own prefix is unset in conn's server, and its other bindings do not apply.

2-6. Three more ways round. esc on the panel goes back into the process last worked in, wherever the cursor has wandered. ctrl-space pressed on the panel goes into the process worked in before that one, so from inside a process ctrl-space ctrl-space is the other process. tab goes to the contact that has waited longest; from inside a process, ctrl-space tab.

2-7. To start work: s opens a shell at the row's project, a a new contact there. p opens the list of every project under the roots, whether anything runs in it or not; typing narrows it, enter opens a shell at the project under the cursor, and esc goes back.

2-8. , opens the settings in the workspace and puts the keys in them; the band reads SETTINGS and the panel goes on reading the machine beside them. The rows are the roots conn walks, each with what it turned out to be on this machine, the themes conn has, and the ground under them. enter on a root types it over, x takes it out, enter on a theme or a ground wears it at once. Under the grounds is ASK THE TERMINAL, which is what conn does with nothing written: it asks the terminal its own background when a server rises. Every change is written to the file as it is made, and esc closes them.

2-9. To leave: q detaches. The server and every process keep running. conn typed again attaches to what is there. conn down takes the server down with everything in it.

KEYS ON THE BAR

The lower row across the foot of the window is the key bar. It names the keys the row under the cursor can take, and no others. Inside a process it names ctrl-space.

SECTION 3

Working the panel

3-1. A contact is Claude Code started by conn, with a, or found running in a project. conn reads the record Claude Code keeps of each instance and takes its word: WORKING while it is busy, WAITING when it has put a question, IDLE at rest. A waiting row blinks. Its page shows the question, how long it has waited, and the keys that answer it. enter goes in to answer; tab leaves it for the next one waiting.

3-2. A contact started by conn is told it runs inside conn, and how to start a dev server or a watcher in a window of the server rather than in the background, so that what it starts is a row on the panel with a pane to go into.

3-3. A lists the sessions Claude Code left suspended at the row's project, newest first, with the branch and the last prompt. Typing narrows them. enter resumes the one under the cursor in a new pane. From the projects list, alt-A does the same for the project under the cursor.

3-4. x ends the row's process, and asks first. The question stands on the key bar as the command about to be run, kill -TERM and the pid, or docker stop, or brew services stop; the band reads CONFIRM. y runs it; any other key withdraws it. A bare shell is sent KILL, since shells ignore the gentler signal. A contact is signalled and not what it runs: the processes under it keep going.

3-5. A container compose started is a row under its project, SERVICE, with the ports it publishes. It has no pane of its own, so enter opens its output, and enter again goes into the pane holding that. s opens a shell inside the container. On a postgres, as a process, a container or a Homebrew service, S opens psql connected to it. o on any row that is running and has a port opens it in the browser, at localhost and the port. A row that had a port and has none, with its process still there, says CLOSED: a server nobody can reach.

3-6. z shows the whole process tree by project, every row nested under what runs it, with its terminal and the age of its state; the band reads TREE. z again is the filed view. c brings the console back over the window. ? opens the man page in the workspace with the keys in it, and puts every key conn answers to on the panel beside it; the band reads HELP, and esc puts the keys back where they were.

3-7. The mouse works on the panel: a click on a row is the cursor to that row. The wheel and a drag are tmux's, and scroll or copy in the pane they land on; the band reads COPY while a pane is in copy mode.

3-8. In the projects list and the sessions list the line is typed into, so a letter is a character there. The line is edited the way readline edits one, and what a letter does on the panel is done with alt: alt-s a shell, alt-a a contact, alt-A the sessions, alt-u what the project declares. ctrl-c detaches from any view.

SECTION 4

What a project declares

4-1. A project may keep a file named .conn at its top, naming the processes that work it: one a line, as name [dir]: command. The name is one word and becomes the row's label. The directory is under the project and is where the process runs; left out, it is the project itself. The command is a shell line, run as written. A line beginning with # is a comment.

# what works this project
web frontend:          npm run dev
api:                   go run ./cmd/api
worker services/queue: make run
db:                    docker compose up postgres
cache:                 brew services start redis

A .conn file: two panes, a compose service, and a Homebrew service.

4-2. Each declared process that is not running is a row at the foot of its project’s block, dimmed and worded DOWN, and the block’s rule says DOWN with it. A project with a file and nothing running in it has no block: rows of nothing but DOWN are a reading of the file rather than of the machine, and the file is where to read it. alt-u on its row in the projects list brings up what it declares, and the block comes with it.

4-3. enter on such a row brings it up in a pane of the server and goes into it. u brings it up and leaves the keys on the panel, so u pressed down the rows brings them up one at a time. U on any row of the project brings up everything it declares and does not have running. The pane carries the declared name on its row.

4-4. When the process ends on its own, the pane holds its output and the row reads ENDED, or EXIT and the code as a fault. enter goes in to read it, u runs it again, and x closes the pane. x on one still running sends it ctrl-c in its pane, the way a hand stops what it ran in the foreground, and closes the pane once it has ended; the row is DOWN again in the one move.

4-5. A process started by hand with the declared command, word for word, in the declared directory, is the declaration too, wherever it was started. Its row carries the name, u and U pass it over, and x signals it as the process it is.

4-6. A command that runs docker compose up has the services compose would bring up as rows under it, each DOWN until it runs, as compose lists them. A command that runs brew services start is the Homebrew service it names, as brew reports it, rather than a pane: ACTIVE with its ports, DOWN until started, EXIT and the code where its last run ended badly. enter on it up follows its log; down, it asks brew to start it. x asks brew to stop it.

4-7. A line that will not read is said under the project's block, with its number, and nothing is guessed at in its place.

THE REFERENCE

Every key, every word the panel and the console can show, the files conn reads and writes, and what each command does are in the man page: man conn, or ? inside conn.
